# ADR-0012 — Bounded portable CLI scaffolding

Date: 2026-10-29. Status: Accepted for an experimental subset of existing Engine #20 under the user's instruction to continue portable work with Core, Composition and code generation while #3 remains Blocked.

Live Project 4 has no Ready cards. Select the portable scaffolding subset of the existing In Progress #20 rather than create a duplicate task or claim that its full #11 dependency is cleared. Preserve W5, dependencies, priority, estimates, unknown actual hours and full task gates. Runtime umbrella maturity remains M0.

Deliver a source-checkout CLI with exactly one profile, `portable-request-reply`. `new` creates a fresh console consumer; `validate` compiles its configuration through existing Composition without activating modules. The generated consumer uses the existing Core dispatcher, immutable Composition plan and actual typed/lazy Roslyn-generated operation registrations. It is a public, unprotected in-process example. It does not provide tenant authority, HTTP/GraphQL/Worker profiles, transport schemas, provider integration or deployment.

The CLI writes a fixed set of text files and never invokes a shell, builds, downloads, installs or starts services. Validate arguments, source inputs and destination before writing. Publish through an owned sibling staging directory and no-overwrite directory move; clean up only that verified owned stage after a failure. Reject observed reparse/symlink ancestors and known Engine/Docs/Samples checkout content destinations. These checks reduce accidental overwrites; hostile filesystem races and mutable source checkouts remain outside the guarantee. An observed source hash manifest is informational and is not immutable Git or distribution attestation.

Generated code validates configuration before activation. The selected app depends on core; an optional disabled module has a failing sentinel factory. All-off configuration must perform no module or handler activation or dispatch. Dispose handlers and activated resources before reporting balanced counters. Unsupported configuration must fail before any activation. The analyzer is a build-time ProjectReference only; consumer runtime dependency inspection must exclude Roslyn and CodeGeneration.

An independent contract suite exercises actual filesystem failures, no-overwrite behavior and deterministic output. A Samples harness invokes the CLI as a process, builds a freshly generated consumer with the pinned SDK, inspects emitted registry source and runtime dependencies, then executes enabled, all-off and invalid configurations. Run the complete bounded matrix on Windows and Linux sequentially and preserve every attempt. See the [predeclared protocol](../validation/portable-cli-scaffolding-protocol.md).

No performance claim or runtime behavior change is intended. A timing benchmark is not required for this bounded file-generation/consumer-correctness slice; full #20 generator-speed/CLI/transport-generation benchmark acceptance remains Planned. The existing Small API benchmark is not repeated or substituted for tooling qualification. Packaging, global-tool installation, NativeAOT/trimming, IDEs, arbitrary source trees, concurrent hostile path mutation and listed-supported Windows qualification remain unproven.
