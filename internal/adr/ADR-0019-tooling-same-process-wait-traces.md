## Clock and attribution boundaries

Keep original workload and clocks unchanged in a separate copied driver. Add repeated UTC sampling bracketed by target Stopwatch **after each body ends**, alongside existing event emission brackets, sequence/PID/nativeTID and old startup anchor. This extra logging is diagnostic overhead and can affect following stages. Freeze and snapshot actual loaded source modules and input binaries before any targets and verify after each lane; no source edits during collection. Preserve every anchor and incompatibility; do not smooth, discard, widen or prorate uncertain data to force alignment.

EventPipe event-to-Stopwatch offsets use marker-write bounds. strace epoch-to-target clocks require explicit bracketed UTC mapping and no unseen wall-clock step between anchors; repeated anchors detect some discontinuities but do not prove none occurred. Per-span/native joins use guaranteed bounds and retain unassigned calls/gaps. Proc deltas require both full endpoint windows on the same nativeTID/birth inside a stage; partial boundary data cannot be prorated or absence interpreted as zero.

A traced futex WAIT call's elapsed interval includes ptrace/scheduling overhead; EAGAIN means value mismatch, not blocked sleep; timeout/interruption/restart/success are distinct. WAKE is not a waiting interval. Managed WaitHandle start→stop is elapsed wait observation, not CPU or proof which thread/object caused delay. GC envelopes and fully-suspended windows remain separate, ambiguities retained. Do not add overlapping GC/JIT/wait/syscall durations as exclusive total. Cross-thread sums can exceed wall time. Selected IO syscalls do not establish physical-disk latency or no mmap/page-fault/9p effects. Shared WSL remains non-reference.
