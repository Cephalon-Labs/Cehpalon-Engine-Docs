# ADR 0008: Explicit protected HTTP and GraphQL operation adapters

Date: 2026-10-28. Accepted for the bounded experimental part of #9/#11; full platform/provider/performance gates remain open. #3 stays Blocked.

Use separate `Transports.Http` and opt-in `Transports.GraphQL` projects. HTTP has no GraphQL dependency. Bind operations explicitly with typed request/response contracts and pure validators; no handler scanning or transport types in business handlers. GraphQL uses pinned Hot Chocolate16.7.1. Its vendor graph remains subject to the W0 license/distribution review; package restore is not public-release approval.

Both adapters call `ITransportOperationDispatcher`. This interface is a host integration point, not an authentication or tenant authority. The consumer must establish a validated identity and route protected calls through `TenantOperationDispatcher`; authenticated flags or headers alone do not supply authority. The Small API consumer uses pinned JwtBearer11 RC3, exact issuer/audience/RS256/token-type/lifetime validation, unambiguous claim representation, then a fresh identity/membership/resource/policy boundary. This process-local synthetic authority is not a real IdP/session/revocation/provider certification.

Small API reuses generated stateless Core gateways and the same tenant-aware catalog business handler for GetItem/ListItems/SetLabel. Request records are immutable snapshots. Data ports demand the checked tenant/catalog/action scope before access. Identical IDs in A/B are legal; metadata headers cannot change scope. Per-record optimistic revision updates are locked inside the bounded in-memory fixture. No durable/idempotent/distributed transaction guarantee follows.

HTTP is protected typed JSON POST with a streamed16KiB bound and structural validation before dispatch. GraphQL is protected HTTP POST only, no IDE/WebSocket/schema download, GET, batching, multipart, introspection, deferred or streamed execution. Depth8 and cost1000 constrain this schema. Explicit inferred DTO fields are the public schema contract and require review when DTOs change; this is not arbitrary user schema support. The same operation validator and domain error codes apply. HTTP status/problem-details envelopes differ from GraphQL field errors; protocol parsing/coercion errors remain transport-specific. Unexpected faults are redacted. Request abort reaches authority and business work; cancellation does not roll back effects already committed.

Compile an immutable Composition plan and reject unsupported capabilities before host construction. API and GraphQL depend on shared host support; GraphQL does not imply the API entrypoint. Do not call GraphQL service registration or map its endpoint when disabled. API-only tests inspect absence of HotChocolate service registrations, disabled endpoint exposure and zero forbidden factory calls through10,000 requests and shutdown; source dependency separation is additionally checked. A combined sample may carry GraphQL assemblies on disk, which is not activation. All-off creates no host/listener. Unimplemented providers have throwing activation traps; absence of those modules is not provider qualification.

The protected fixture has20,000 records (10,000/tenant) and independent functional checks. It does not execute or redefine the original public W0 workload. Its startup timing is diagnostic only. Full isolated paired latency/footprint benchmarks, 1,000-case original corpus,100 timed cancellations/profile and30 restart cycles remain Not run. Windows26H2 results are observational; WSL listed-distribution results do not clear supported-Windows #3 or prove production deployment.
