# ADR0014 — Offline Small API transport contract export

Date: 2026-10-29. Accepted for the continuation of existing #20 after the generated Small API profile. A narrow HTTP serializer-schema helper supports this work under #9. #3 stays Blocked; original full gates, dependencies, estimates and M0 remain unchanged.

The generated consumer adds `--export-contracts --config <json> --output <new-directory>`. The CLI continues to generate source only; the caller explicitly builds/runs the consumer. Export compiles the same Composition graph/capability rules before output or schema services. API-only writes OpenAPI3.1 JSON, GraphQL-only writes SDL, combined writes both, and all-off writes only a manifest. Disabled transports produce no contract artifact or transport-owned service registration. Export does not construct WebApplication, import keys, open a listener, resolve tenant authority or dispatch business work.

Use a shared typed transport catalog for actual endpoint mapping and artifact production. Opaque endpoint delegates cannot supply authoritative request/response types to an endpoint scan. HTTP JSON schemas come from BCL JsonSchemaExporter through the actual adapter's serializer policy; return detached schema nodes without exposing mutable transport options. Apply the adapter's object-body requirement in the OpenAPI request schema. The bounded OpenAPI describes the three current operations, literal POST routes, JSON responses, bearer requirement and real error envelope/media types; it is not arbitrary endpoint discovery.

GraphQL SDL comes from the pinned HotChocolate executor's real schema, using the same shared GraphQL catalog as serving. Building that schema is explicit offline artifact work: disclose service/provider/schema construction and await provider cleanup. It is not a claim of zero GraphQL work when GraphQL is selected. No GraphQL registration/provider/schema work occurs when disabled. Schema compilation has a throwing dispatcher and lazy generated-handler factory, with counters proving no execution. Compare the actual generated registry operation IDs to the typed catalog without constructing gateways/handlers.

The exported schemas describe structural serialization/type contracts. They do not encode arbitrary validation lambdas, duplicate-key/UTF-8/body-size parsing rules, numeric parser implementation limits, token validation, fresh membership/revocation or tenant authorization. Demonstrate this boundary with a shape-valid but domain-invalid request rejected by actual HTTPS. Do not manufacture constraints or claim that schema acceptance grants access. Offline export does not enable HTTP introspection/schema/IDE/GET/WS endpoints.

Outputs use deterministic bytes without timestamps/output identity, fresh-directory staging and no-overwrite publication. Reject observed reparse ancestry and known program checkout content targets, preserving trusted-parent/TOCTOU limits. Only verified owned expected files may be cleaned; retain unknown changes. Failure diagnostics report actual schema construction/disposal counters even after late publication failure. All-off/invalid plans avoid credentials and business work.

The new ContractExport.cs template intentionally advances Small API output from13to14files. Portable defaults remain9files/17inputs; selected Small API source inputs remain32if the helper is added in the existing HTTP adapter file. Preserve actual source inventories, including embedded templates. See the [predeclared protocol](../validation/tooling-contract-export-protocol.md).

This slice makes no performance claim. Timing benchmark is Not required for bounded artifact correctness; full #20 tooling benchmark, reference/platform/provider qualification, distribution, arbitrary schema generation and production acceptance remain open. Sources: [BCL schema exporter](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/extract-schema), [OpenAPI3.1 specification](https://spec.openapis.org/oas/v3.1.0.html). Actual compatibility is proved against pinned SDK11RC3/HotChocolate16.7.1, not inferred from later documentation.
