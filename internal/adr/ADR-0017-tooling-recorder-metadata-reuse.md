# ADR0017 - Reuse recorder JSON metadata without changing benchmark criteria

Date: 2026-10-30 (Asia/Bangkok). Accepted within the user's explicit #20 variability-improvement request, after the complete first candidate at Engine1b9d538. Keep #3 Blocked and all full task gates/metadata unchanged.

Candidate01 is complete and retained, not a discarded preparation run. Windows generator unstable distributions increased4 to6, Linux3 to5. Windows CLI export-off CV fell15.220958% to10.336723% while its mean rose320.04 to332.68ms. CLI and generator results cannot be summarized as an overall improvement. All correctness, registry and export artifact checks passed. See the retained comparison for exact values; no selected rerun is authorized by these numbers alone.

Additional source inspection found that the benchmark journal creates a new JsonSerializerOptions instance for every raw row. This repeats options construction and cache lookup/association outside the declared generator/emit clocks and can affect later process allocation/GC state. The runtime may share metadata between equivalent options; repeated metadata rebuilding is not established by source inspection. Its contribution to observed timing variation is a hypothesis, not an isolated measured cause. A fixed diagnostic will compare100serializations of the actual recorded Measurement DTO schema with per-call versus reused compact options, recording allocation and exact output equality; it will not time generator work or establish an application performance result. Preserve diagnostic source, inputs and every result before any correction.

Reuse one compact camelCase options instance for the append-only raw journal, separate from the existing pretty final report options. Make no other collector/cache/fixture or generator work change. Keep every row and flush/write, error context, clock boundary, order, version, seed, semantic/emit check, CPU zero, GC policy, count, primer, repetition, percentile and descriptive15% threshold from the original protocol. No extra warmup, collection, latency floor, filtering or process/runtime flag. The orchestrator remains byte-identical. Cached serializer metadata is an implementation improvement to already excluded recorder work, not movement of measured work outside a clock.

This subsequent source revision supersedes ADR0016's unchanged-driver constraint only for that compact journal serializer. Preserve Candidate01 and the original baseline alongside Candidate02; compare all complete series, including regressions. Rerun exact-source components and the entire original Windows then Linux benchmark once for Candidate02 after source review. Runtime/templates/generator algorithm remain identical to Candidate01, whose full actual Small API/export/portable regressions remain identified by their own revision; they are not relabeled as Candidate02 runs.

Report recorder allocation evidence separately from end-to-end generator/CLI observations. The historical runs are not a controlled causal experiment and reducing recorder allocations does not guarantee lower CV.
