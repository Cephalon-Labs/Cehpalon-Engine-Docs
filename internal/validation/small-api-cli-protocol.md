# Small API CLI/profile correctness protocol

Declared 2026-10-29 before integration validation. Scope ADR0013 and existing #20; #3 remains Blocked with unchanged issue body/editable metadata. Full task gates, dependencies, estimates and M0 are preserved.

Use pinned SDK11.0.100-rc.3.26522.148 and official-only locked package graph. No runtime library semantic changes are planned. Keep every attempt and report uncommitted integration separately from final clean exact Engine revision. Final Windows then Linux correctness runs are sequential on the shared host. Existing Engine and portable CLI suites must still pass; hosted CI is checked independently.

Required checks:

- Existing portable CLI contract/output behavior remains compatible. New profile selection, strict arguments and profile-specific pure validation fail with redacted structured diagnostics. Unsupported capabilities reject before host/factory/key I/O.
- Same source/name/profile produces identical published file bytes at two destinations. Existing targets are untouched. Inject failures before/after every new-profile file write and publication failure; only owned staging is cleaned. Keep existing path/checkouts/link/device protection. Source inputs are observed hashes, not immutable attestation.
- Invoke actual CLI to generate a new consumer into an ignored path with spaces/Unicode/ampersand; final proof uses a real clean Engine clone with similarly escaped source path. Inspect the new emitted project and compile it with initial actual package lock, locked restore and Release warnings-as-errors. Capture exact source hashes, commands, logs and emitted registry. Compiler/Tooling dependencies must not enter the runtime graph; optional GraphQL packages on disk are disclosed separately from activation.
- The actual generated consumer reads its shipped appsettings. Execute API-only, API+GraphQL, GraphQL-only, all-off and invalid plans. API-only has zero GraphQL service registration/mapping/factory work; GraphQL-only has no API entrypoint; all-off has no WebApplication/store/listener/handler work and must ignore nonexistent key paths. Forbidden Worker/database/cache/broker/AI/retrieval module factories stay zero.
- Real HTTPS requests prove both A-to-B/B-to-A tenant denials, same IDs isolated, untrusted subject/role/tenant headers ignored, bad/absent JWT rejected, fresh membership revocation/resource owner/default-policy denial before business work, and valid tenant operations/optimistic updates. Preserve the distinction between protocol authentication and tenant authority.
- Validate TLS custom trust/hostname, GraphQL exposure restrictions, validation/malformed/oversized input, cancellation observed after handler entry with no delayed write, and handler/module/listener cleanup. Do not interpret passing cancellation ACK alone as in-flight proof.
- Serve mode requires explicit caller TLS/public-key/config/readiness inputs, binds loopback and does not implicitly issue credentials. All-off and invalid configurations avoid credential reads; readiness uses a new complete publication, contains no secrets and does not overwrite existing data. Keep timeout/failure logs; exclude private keys/certificates/dumps from committed evidence.

All required correctness checks must pass. Retain failures and fix causes; rerun the complete bounded matrix after a source fix rather than select favorable cases. Test counts describe this matrix, not full #20/#11/platform/provider coverage. No timing threshold, performance comparison or old Small API benchmark rerun is required here. Full tooling benchmark remains Planned; no performance or production claim is made.
