# Operation budget drain validation

The Core and tenant admission budgets close permanently when a host calls DrainAsync. Both reject later admissions with the generic capacity error and let admitted work finish including cleanup. Canceling a wait only affects that waiter. Concurrent and late waits observe the same terminal condition. Cleanup faults remain on the operation that owns the failing handler. The protected route still checks authorization before consulting the budget.

Use controlled cleanup gates to prove Core and tenant closure while below the numeric limit, cancellation of one waiter, two concurrent waits, rejection across dispatcher instances, completion while another handler faults, and immediate idle closure. Test the generated host using both budget variants. During shutdown it closes admissions before Kestrel stop, retains an active protected write and waits for the owned read or write and host cleanup within its existing shutdown bound. Preserve default, combined-budget and all-off regression cases. This is a correctness protocol. The established benchmark gates remain as recorded.

Measure the added closure check with the existing W1 Components `--observe-dispatch-budget` harness. On each host use the already built exact baseline and candidate artifacts. Windows order is baseline then candidate. WSL order is candidate then baseline. Run each revision once per host after the builds and correctness tests have finished. The harness warms 10,000 calls per path and measures five alternating pairs of 100,000 synchronous calls without forced collections. Preserve each pair and compare median nanoseconds and allocated bytes per operation, plus the within-run budget-versus-direct difference. These are descriptive observations without a pass threshold or an inference about throughput or the canonical gates.
