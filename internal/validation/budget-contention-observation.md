# Budget observation under concurrent dispatch

Use the pinned SDK and exact committed Tenancy.Components binary. After builds and correctness checks finish, run one complete Windows attempt followed by one complete WSL attempt with --observe-budget-contention. Retain every pair. The original benchmark protocols and thresholds remain as recorded.

Five alternating pairs compare a waiting observer with a continuous snapshot observer. Each lane uses a new shared tenant budget with total capacity eight and per-tenant capacity two. Four independently scheduled dedicated producer threads each use a distinct fixture tenant and perform 25,000 synchronous authorized operations. There are no queued requests or network/provider calls. Warm each dispatcher with 1,000 operations before timed work and reset fixture counters. One dedicated observer thread is created in both modes. In the control it waits for completion; in the observed lane it continuously reads and validates snapshots until signaled after producers finish. All actors acknowledge readiness before a common start signal.

Record wall-clock ticks from start release through producer completion and observer join, per-producer current-thread allocated bytes and checksum, observer current-thread allocations, read count and measured loop ticks, and exact authority/factory/disposal counts. Each lane must complete all 100,000 successful operations with expected checksums, one fresh authority pass per operation and one owned cleanup per factory. Every observed snapshot must satisfy limits, active-tenant/operation consistency and open admission. After actors stop, require empty state, drain the budget and verify empty closed state. Observer loop ticks include pauses, scheduling and lock waits. Report full lane medians and signed paired differences with no speedup or qualification threshold. This shared-host comparison cannot attribute an observed difference solely to lock contention or extrapolate a monitoring frequency.

Use one signed 64-bit value containing a 31-bit active operation count, a 31-bit active tenant count and a closure bit. Configured limits are immutable fields.
