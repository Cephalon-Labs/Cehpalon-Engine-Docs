# Dynamic scheduler native preflight under ADR0030

Date 2026-11-05. Kernel `6.18.54.1-microsoft-standard-WSL2`, x86-64 Ubuntu WSL. The loaders check the exact live BTF length and SHA-256 from ADR0030. Freeze the sources, commands, fixed instruction templates and target layout before calling BPF. Run the probes sequentially as root. Keep a separate exit status, stdout and stderr for each.

1. **Storage verifier.** Load 65 bytes of key/value BTF, create one `TASK_STORAGE` map with four-byte key, eight-byte value, `BPF_F_NO_PREALLOC` and zero max entries, then load the 11-instruction raw tracepoint program unattached. It looks up the current typed task without creating a slot, checks for null, reads a cookie and returns zero. Close program, map and BTF descriptors. FD values in the map attribute and pseudo-map instruction are the only dynamic template slots.
2. **Held owner.** After storage verifier success, create fresh BTF and map objects. Hold one controlled Python child at UID/GID 1000, with empty supplementary groups, zero effective/permitted/inheritable/ambient capabilities and a ten-second watchdog. Verify direct parent, executable, PID namespace, local PID, start ticks, one thread and two independently opened live pidfds. Require initial absence, seed, alias read, duplicate rejection, original cookie retained, collector absence, delete via alias, owner absence while live and owner absence after release and reap. Recheck the lease before release. Pass requires nine expected results, five explicitly closed BPF or pidfd descriptors, clean actor exit and successful pipe cleanup. This is userspace map access through pidfds. It is separate from executing a typed-current lookup in a hook.
3. **Scalar target verifier.** Independently load one eight-instruction raw tracepoint program with a guarded four-byte read from scalar context slot 0 plus offset 20. The intended hook is `sched_waking`. Exact kernel source and the pinned BTF identify the target task and its `thread_info.cpu` field. The verifier load establishes instruction acceptance before any hook is named or attached. Close the program descriptor.

Use one attempt per declared probe. Keep any rejection as evidence. A source correction requires a recorded reason and a new frozen declaration. These probes use ephemeral resources, no attach, no trace output, no pinning and no host setting changes. No synthetic thread lifecycle or Roslyn launch is in this declaration. `capture_ready` remains false.

Source basis includes the [pinned task-storage implementation](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/bpf_task_storage.c#L77-L196), [pidfd lifetime](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/fs/pidfs.c#L165-L250), and [wake tracepoint definition](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/events/sched.h#L139-L190).
