# Budget snapshot observer-cost protocol

Use the pinned SDK in Release and the exact committed Tenancy.Components binary on each host. One fixed run on Windows then one on WSL follows completed builds and correctness checks. Run the new explicit --observe-budget-snapshots mode. The original tenant benchmark path and criteria remain as recorded.

Observe four stages in order: idle/open, one admitted operation waiting in cleanup, closed admission with that operation still in cleanup, then fully drained. At each stage freeze and validate Core and tenant snapshots. Warm each reader with 10,000 reads. Run five repetitions of 1,000,000 reads per lane, rotating lane order by repetition across cached Core value, actual Core getter, cached tenant value and actual tenant getter. Each lane invokes a prebuilt typed delegate and folds all snapshot fields into a checksum. Measure monotonic elapsed ticks and current-thread allocated bytes for the loop. Validate each checksum and all state transitions. Record every repetition and publish the complete series.

Cached values provide a description of delegate and checksum cost under the same loop. Values in the table include that overhead. Report raw lane medians and paired differences without a pass threshold. No forced collections, outlier filtering, best-run choice or unchanged-source reruns. The held operations use real Core and tenant dispatch with cleanup gates, so active counts represent owned work. Setup, JSON serialization, gate transitions and output writes are outside the measured loops. This protocol has one observer thread and no concurrent mutation during a measured stage. Serialization, exporter behavior, contention and request throughput need their own evidence.

Before the observer series, execute the existing default Tenancy.Components smoke once on Windows and once on WSL from the same binaries. Preserve its existing iteration counts and five guardrails. This checks routing through the original entry point after adding the explicit observer mode.
