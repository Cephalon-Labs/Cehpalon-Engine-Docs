# CLR ThreadPool boundary hooks and observer overhead

Engine #20 and [ADR0031](../adr/ADR-0031-roslyn-same-execution-scheduler.md). The [fixed protocol](../validation/clr-threadpool-boundary.md) compares lifecycle capture with the same collector plus two worker-only scheduler boundary hooks on the unchanged CLR pipe fixture.

Attempt 01 stopped at the original kernel check before launching an actor. WSL now runs 6.18.58.1. A fixture-specific host profile pins its BTF and checks every task and PID offset used by the collector, the target CPU field and the two raw bool prototypes. Nine source files from the published Linux tags were compared. Eight matched byte for byte. The scheduler core differed in one PSI IRQ accounting argument outside the relevant hooks. Source and BTF checks establish the declared ABI for the test. [Microsoft kernel source comparison](https://github.com/microsoft/WSL2-Linux-Kernel/compare/d504d40ab83839cb61942a812a99d183c42227b9...a989171929bed4ea681be8d77333845ce1c1732a)

Attempt 02 completed all 11 cases in order. All six executions with the extra hooks bind the managed callback to its native generation, newborn exit and returned switch invocation. The raw replay reconciles 942 boundary rows, 453 complete switch pairs, 18 newborn prefixes and 18 final retired entries, with six pairs whose endpoints use different CPUs. No no-switch pair or true preempt-mode entry appeared in this CLR workload. Both ledgers and second reads reconcile, with no reported loss, recursion misses or cleanup errors. The focused suite passes 29 tests per host on Windows and WSL.

The observed incremental cost on 64 fixed pipe round trips was +16,984, +196,096, +204,360 and +190,668 ns for the four measured pairs. Median +193,382 ns. Each arm used the nine original lifecycle hooks. The retained primer is outside the measured summary. These values describe observer overhead in this shared WSL fixture.
