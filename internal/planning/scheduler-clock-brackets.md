## Fixed native results

The first ordered attempt completed the capacity-negative and fresh positive cases. The negative offered two owned gettid calls, retained one row and counted one capacity loss. The positive offered 64 calls, 32 on CPU 0 and 32 on CPU 1 in eight alternating batches; all64rows were retained with zero loss. Both cases have exact terminal/second-read counter and ledger reconciliation, zero unused slots, zero reported recursion misses, stable held-process leases, task-storage alias confirmation and post-reap absence. Unseeded owner, nonmember and wrong-syscall controls leave counters at zero. The root nonmember syscall is invoked by frozen source and has storage/counter receipts, but its numeric return value was not separately retained. Each case closes all nine explicitly owned native FDs without forced actor cleanup.

## Accessor and observation boundaries

The actor runs at UID/GID 1000, without capabilities or extra groups, as a held single-thread Python process. Its startup uses -I/-S before the first native source freeze; this isolation delta from the earlier readiness review is recorded. Root verifies pidfd aliases, live start/namespace/executable/credential identity and seeds only that task's storage. The program checks typed-current ownership and exact gettid186 before clock reads or counters. It snapshots CPU before the first fast point, reserves/writes its ledger row, samples the second fast point, then snapshots CPU again. These are inner callback-body boundaries after ownership checks. They do not represent full hook, syscall entry/exit or physical context-switch boundaries.

The actor's actual [raw clock syscall](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/arch/x86/entry/syscalls/syscall_64.tbl) uses228/CLOCK_MONOTONIC1 and reaches the [normal seqcount-retry accessor](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/time/timekeeping.c#L955). It bypasses vDSO and fast-view helpers. It still shares the kernel timekeeper and physical clocksource with the [fast helper](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/helpers.c#L177). Common-mode error, unobserved updates, other hosts and other executions are outside these brackets. Source/release/BTF and hash equality are provenance observations, without immutable installed-image/JIT attestation.

All 99 tool-source files and three binary/BTF artifacts were frozen and checked unchanged around the native pair. The exact host and zero-offset actor/collector time namespace were verified. Focused tests pass 124 each on Windows and WSL. The independent native audit passes 629 checks without importing the production program builder or analyzer. Source feasibility review passes 37 checks over 17 immutable primary files. The visual readiness inspection preceded the isolation edit; readiness source hashes were sampled after it and match the actual frozen sources. Both observations remain explicit and provide no immutable executing-source attestation. Full raw/failed-source preparation history is retained; this native pair had no rejected predecessor or selected retry.

## Later switch-boundary scope

Exact [source declarations](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/events/sched.h#L882) and pinned BTF identify raw hooks sched_entry_tp(bool preempt) and sched_exit_tp(bool is_switch). The [DECLARE_TRACE bridge](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/bpf_probe.h#L120) supplies raw map entries. Availability of an actual scoped attachment remains untested here.

The [scheduler callsites](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/sched/core.c#L6817) place entry before selection, sched_switch before context_switch and sched_exit after the restored invocation returns. Pairing solely by CPU is invalid: the incoming thread resumes its own saved scheduling stack, potentially after migration. Newborn [schedule_tail](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/sched/core.c#L5258) emits exit(true) without a prior entry for that thread; exit(false) can represent a no-switch path. Future attachment must bind current owned generation/invocation, raw bool, sequence, CPUs and lifecycle, with unknown prefixes and explicit newborn/no-switch controls. No fentry or unrestricted trace is authorized by source visibility alone.
