# Observing one CoreCLR GC wait callsite on an owned worker

The pinned .NET 11 RC3 Linux runtime is stripped. Its Microsoft symbol companion matches its executable build ID, SHA-256 inventory and debuglink CRC. The DWARF line table places the instruction at virtual address `0x14156e` under the call on source line 2171 of `Thread::RareDisablePreemptiveGC`. The stripped executable's virtual call and vtable relocations resolve the workstation and server implementations of `WaitUntilGCComplete`. The fixture uses workstation GC. ELF executable-segment translation gives file offsets `0x14056e` for the call instruction and `0x140574` for the first instruction after it. The runner also checks the installed instruction bytes. [Pinned CoreCLR source](https://github.com/dotnet/runtime/blob/474ed963699fc29809015392738a15231aaae2de/src/coreclr/vm/threadsuspend.cpp#L2168-L2175) · [Microsoft symbol tooling](https://learn.microsoft.com/dotnet/core/diagnostics/dotnet-symbol)

One WSL 6.18.58.1 fixture used two initially disabled perf descriptors attached to the same named, ordinary-user worker TID. The coordinator checked the owned child PID, TID and executable mapping inode before attachment and after each drain. During the ordinary native sleep control the collection deltas were zero and neither instruction produced a sample. During 12 explicit full blocking compacting collections, the same worker produced two ordered call/return pairs. The descriptor counters matched all four decoded perf samples, with zero reported loss. The fixture exited normally and the coordinator verified the worker process had been reaped. There were no global perf targets or host settings changes. [Frozen protocol](../validation/coreclr-gc-wait-callsite.md)

The positive fixture establishes that the two probes can identify traversal of this particular runtime callsite. The implementation has a fast return, so a pair does not establish physical blocking or delay caused by GC. The earlier Roslyn waits have no callsite samples. A later Roslyn capture needs separate validation for worker birth, enrollment, loss and correlation with managed GC and native lifecycle events. No Roslyn or benchmark run was part of this fixture. The focused perf-ring suite passed four tests. [Delivery](../evidence/coreclr-gc-wait-callsite/delivery.json)
