# CoreCLR wait-object identity across reset, wait and set

The pinned workstation CoreCLR image loads the same `WaitForGCEvent` global into `RDI` at the exact wait, set and reset branch sites. Verified file offsets are `0x1f3f2b`, `0x1c3cdc` and `0x1c3cfc` respectively. Those operands are the `GCEvent*` wrapper. The running WSL kernel's pinned BTF places `pt_regs.di` at offset 112. One TGID-scoped link attached the three sites and the two verified call/return sites before either worker's birth. Only the event operand at the three dedicated sites is read. [CoreCLR source](https://github.com/dotnet/runtime/blob/474ed963699fc29809015392738a15231aaae2de/src/coreclr/gc/gcee.cpp#L263-L308) · [WSL register layout](https://github.com/microsoft/WSL2-Linux-Kernel/blob/a989171929bed4ea681be8d77333845ce1c1732a/arch/x86/include/asm/ptrace.h#L97-L120)

Both no-GC arms produced zero records. The same-image peer traversed seven reference callsite pairs without producing any record on the target link. Across the two target arms of 20 explicit collections each, the ledger contained 40 resets, 28 waits, 40 sets and 28 call/return pairs. All 108 object-bearing receipts carried the same wrapper identity. Twelve exact calls were on the two named newborns and sixteen were on pre-existing threads of the same owned process. Both native ledgers reported zero loss or faults. The detached object reads were identical and the uprobe program reported zero recursion misses. [Frozen protocol](../validation/coreclr-gc-event-object.md)

Each newborn contributed one strict chain. The process leader reset the event. The worker entered the exact CoreCLR call and reached the wait branch, then the scheduler recorded its switch-out. The leader reached the set branch for the same object before the worker's recorded waking, wakeup, switch-in and call return. The independent raw audit confirmed the order and each scheduler slot. The other call pairs did not meet the full chain predicate. The setter site observes the branch into `GCEvent::Set`, before the operation publishes the signaled state or broadcasts. The receipts therefore identify the event wrapper and a distinct setter thread, while the exact kernel wake caller and physical timing components remain open.

Nine focused tests passed. The evidence capsule retains execution-local equality tokens and hashes of both the original private operand ledger and the exported receipts. The fixture ran once, without any Roslyn or benchmark run. #20 remains In Progress, #3 remains Blocked and the original benchmark gates apply.
