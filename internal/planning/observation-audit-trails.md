## Project-selected audit history and trails

Projects select Disabled, MetadataOnly, ChangedFields or BeforeAfterSnapshots through immutable project policies and exact operation/action/resource-kind field rules. The whole module is opt-in; disabled sink/history provider factories and constructors are zero. MetadataOnly and empty field allowlists never invoke the values factory. Other modes call one trusted state factory and project only allowed fields. Before/after state is immutable bounded scalar data; Missing differs from Null, and typed comparisons preserve WasChanged before redaction. Secret fields receive fixed markers before storage. Current read policy projects older records again and cannot invent richer state than the original CapturedMode.

Receipts come explicitly from trusted application/provider mutation handling, not automatic request/result diff or verified database CDC. Match receipt principal/issuer/scheme/tenant/operation/action/entity/authorization-resource version with active checked context. Domain entity before/after versions remain separate from ACL/resource-scope versions. RecordedAtUtc is observed; optional ReportedAtUtc is provider supplied. Receipt IDs support the provider's idempotency contract, without a fabricated automatic-operation InvocationId/caller-correlation link.

Field history requires distinct audit-trail/tenant/read authority; ordinary operation-history permission is insufficient. History validates page limits/tenant ownership and checks the lease after asynchronous read and projection. Omitted/secret fields are removed/redacted again under current policy. Explicit capture rules can persist supplied domain data, so projects must omit credentials/session IDs and render text through structured escaping; this is not automatic secret discovery or arbitrary object capture.

Required post-receipt persistence can fail after data changed or after a record reached the store. TenantChangeAuditWriteException carries MayHaveCommitted, including wrapped post-receipt caller cancellation. Unhandled component failures produce operation Faulted. The sample deliberately returns audit_trail.write_failed_may_have_committed and operation Rejected, preserving the possibility of committed effects. No automatic retry/rollback/exactly-once or real transaction/outbox/retention/tamper-evidence guarantee is inferred.
